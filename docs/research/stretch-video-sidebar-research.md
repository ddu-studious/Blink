# 拉伸动作并排视频播放 - 技术调研

**版本**: v1.0  
**创建日期**: 2026-02-25  
**状态**: 已完成

---

## 1. 调研背景

青眸护眼应用的长休息模式中已有拉伸引导功能，包含 10 组动作，每组动作有步骤文字引导、自动计时和重复循环。当前视频功能为底部按钮触发全屏切换播放，**步骤引导与视频播放互斥**——用户无法在跟练视频的同时看到当前步骤进度。

用户期望：**在每组动作执行时，旁边直接显示教学视频**，实现「看视频 + 看步骤」的并排体验。

---

## 2. 技术可行性分析

### 2.1 iframe 嵌入（B 站 / YouTube）

| 维度 | B 站 | YouTube |
|------|------|---------|
| **可行性** | ✅ 可行 | ✅ 可行 |
| **嵌入地址** | `player.bilibili.com/player.html?bvid=xxx` | `youtube.com/embed/{videoId}` |
| **CSP 配置** | 已支持（`frame-src https://player.bilibili.com`） | 需增加 `https://www.youtube.com` |
| **自动播放** | 支持（`autoplay=1&muted=1`） | 支持（`autoplay=1&mute=1`） |
| **播放控制 API** | ❌ 无 JS API | ✅ YouTube IFrame Player API |
| **国内可用性** | ✅ | ❌ 需翻墙 |

### 2.2 本地视频方案（HTML5 `<video>`）

| 维度 | 说明 |
|------|------|
| **可行性** | ✅ 可行，需注册自定义 protocol（`stream: true`） |
| **离线可用** | ✅ |
| **包体积影响** | 480p 10-30 秒视频约 1-3 MB/个，10 组约 10-30 MB |
| **版权问题** | 需自行解决视频版权 |
| **播放控制** | ✅ 完整 HTML5 Video API |

### 2.3 结论

**推荐方案：iframe 嵌入 B 站/YouTube，作为并排视频源。**

理由：
1. 零包体积增加
2. 无版权风险（使用官方嵌入）
3. 技术已验证（当前全屏切换模式已在使用）
4. 视频内容丰富且持续更新

## 4. 布局方案设计

### 4.1 方案 A：左右分栏（推荐）

```
┌────────────────────────────────────────────────────────────┐
│  🌿 长休息 · 拉伸一下                           ⏱ 4:32   │
├──────────────────────────────┬─────────────────────────────┤
│                              │  侧弯拉伸                   │
│    [ B站/YouTube 视频 ]       │  🎯 腰部 · 建议 50 秒       │
│    比例 16:9                 │                             │
│    宽度约 55%                │  ✓ 坐直，右手举过头顶        │
│    自动播放、静音             │  ● 缓慢向左侧弯 ... 8s      │
│                              │  ○ 缓慢向右侧弯 ...         │
│                              │  ○ 重复 2 次                │
│                              │                             │
│                              │  ━━━━━━━━━ 40%              │
│                              │  💡 保持臀部稳定             │
│                              │                             │
│   🔇 点击开启声音             │  [下一个动作]               │
└──────────────────────────────┴─────────────────────────────┘
```

**优势**：视频与步骤同时可见，视觉冲击力强  
**适用**：全屏覆盖窗口（1280px+ 宽度）

### 4.2 方案 B：上下分栏

```
┌────────────────────────────────────────┐
│    [ B站/YouTube 视频 ]                │
│    高度约 40-45%，16:9                 │
├────────────────────────────────────────┤
│  侧弯拉伸  🎯 腰部                    │
│  ✓ 步骤 1  ● 步骤 2 (8s)  ○ 步骤 3   │
│  ━━━━━━━━━ 40%                        │
│  💡 保持臀部稳定                       │
└────────────────────────────────────────┘
```

**优势**：布局紧凑，适合较小屏幕  
**适用**：1024px 以下或竖屏

### 4.3 方案 C：可折叠视频面板

默认显示步骤引导，视频面板可展开/收起。适合作为 fallback 或网络不佳时。

### 4.4 推荐策略

- **宽屏（>= 1280px）**：左右分栏，视频占 55%
- **中等屏幕（1024-1280px）**：左右分栏，视频占 50%
- **小屏 / 无网络**：不显示视频，保持当前纯步骤布局

## 5. 技术实现要点

### 5.1 CSP 更新

需在 `src/renderer/index.html` 的 CSP 中增加 YouTube：

```
frame-src https://player.bilibili.com https://www.youtube.com;
```

### 5.2 视频与步骤同步

| 场景 | 处理 |
|------|------|
| 动作切换 | 视频跟随切换（更新 iframe src） |
| 用户跳过 | 视频停止，切换下一个 |
| 网络断开 | 隐藏视频区域，仅显示步骤 |
| 视频加载中 | 显示骨架屏/loading |

### 5.3 自动播放策略

- 默认 `muted=1` + `autoplay=1`，保证自动播放
- 提供静音/取消静音切换按钮
- B 站参数：`&danmaku=0&high_quality=1`

### 5.4 性能考量

| 维度 | 影响 | 措施 |
|------|------|------|
| 内存 | iframe 创建独立渲染进程 | 切换动作时销毁旧 iframe |
| CPU | 视频解码 | 480p 足够，无需高清 |
| 网络 | B站/YouTube CDN | 仅 Long Break 时加载 |

## 6. 风险评估

| 风险 | 严重性 | 概率 | 缓解措施 |
|------|--------|------|----------|
| 视频下架/失效 | 中 | 中 | 每个动作配 2+ 备选视频 |
| 网络不可用 | 低 | 中 | 降级为纯步骤引导 |
| iframe 加载慢 | 低 | 低 | 显示 loading，不阻塞步骤计时 |
| B 站嵌入策略变更 | 中 | 低 | 关注官方文档，可切换 YouTube |
| 占用过多内存 | 低 | 低 | 切换动作时销毁旧 iframe |
